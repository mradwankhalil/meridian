## Interpretation and remaining gates

1. The candidate's original `BLOCKED_PROVIDER_REFUSAL` verdict is a retained harness classification error. It treated the four `error_max_turns` tool checkpoints as provider failures. The recorded HTTP statuses, subsequent paired tool results, two final successful SDK results, receipt and client exit do not show a provider HTTP refusal. Preserve that original report and explain the offline reclassification; do not describe it as a repaired runtime error or green rerun. A future harness should label an `error_max_turns` terminal expected only after verifying the delivered tool checkpoint and following result.
2. All native request model IDs and SDK init IDs request/name Fable 5.1; the SDK tool assistant records report `claude-opus-4-8`, while the two answering queries report `claude-fable-5-1`. The model-identity gate therefore remains open. Do not infer the cause, assert every tool inference was Fable, or use Meridian's Fable response-model label as proof of served identity. The harness selects no substitute/fallback model.
3. The analyzer's recorded usage test fails the 95% threshold on every evaluated resume pair in both arms. Candidate subagent ratios are approximately 50.29%, 50.27%, and 0%; parent ratio is 0%. These are failures of the recorded acceptance metric, not a proven cache regression or diagnosis. Mixed model identities and aggregate SDK accounting limit stronger attribution.
4. Before-request immutable-source snapshots, a separate unchanged-tail live negative control, the durable-tail edit live regression, all four E41 modes, an ordinary saved-session follow-up, and actual reminder-only shape are not established here. The continuation of the parent after the Agent result is not a separate saved-session CLI restart/follow-up.
5. Candidate v1 has `configOwned=false` from the obsolete equality check against `sdk-config`; OAuth profiles intentionally use an isolated profile directory. It records no config locator digest/path sufficient to independently repair that witness offline. Candidate also has no retained telemetry or route-log rows; baseline has explicit native-adapter telemetry. Treat candidate adapter/config proof as narrower than baseline's and do not retroactively apply the improved harness checks to the old run.
6. The candidate report does not contain build, lock or harness hashes; its retained v1 harness is available separately. The baseline report records current harness, dist and lock hashes. The v1/current diff preserves inference prompts, client arguments, selected model and request forwarding; it changes instrumentation, verdicts and cleanup. These were equivalent stimulus arms with distinct harness revisions, not execution of byte-identical harnesses. Candidate build provenance needs the parent's separate build/install receipt; source HEAD alone does not attest an imported bundle.

## Analyzer qualifications

The analyzer correctly retains `LIVE_ACCEPTANCE_INCOMPLETE`, explicitly lists missing gates and derives both transition pairs and checkpoint relationships from sanitized observations. It does not fabricate an acceptance success.

For future stronger use, the analyzer should bind its own source/dependency provenance to the recorded arm, reject missing per-query served identities rather than rely on an aggregate model set, and verify exact owned fixture paths/results rather than the `fixturePathOwned` substring test. `everyCallHasExactlyOneRealResult` does not by itself reject an additional denial or unmatched result, although none appears in these retained call/result lists. `publishedTargetMatchesObservedQuery` proves membership in an observed query, not that the mapping is the exact latest answering query for a particular agent. Public-history summaries cannot be regenerated from sanitized JSON alone once private owned session state is discarded; retain them as captured summaries and keep raw SDK/client state private.

No credential patterns, credential/env/body/content keys, or raw private transcript text were observed in the four reviewed JSON artifacts. All four are mode 0600. The reports contain owned fixture command text, digests, block kinds, model/usage metadata and safe empty diagnostics. This is scoped inspection, not proof about every file under the evidence root. Escrow the sanitized artifacts only; SDK/client configuration and session directories automatically contain private state and must not be archived indiscriminately.
