## #1411 concrete finding and proof

**P2 — the last visible URL-selected provider cannot be hidden durably.**

At exact head `4036dd9b`, `profileProviders.ts:212–224` serializes the selected set on chip clicks. Hiding the last selected chip writes `?provider=`. `profileFilterUrl.ts:35–38` converts an empty selection into null, and `profileProviders.ts:205–208` then reloads the saved preference. Thus address no longer reproduces the visible view, contradicting the feature's reload/permalink promise.

Example with saved `meridian.hiddenProviders=[]` and both providers present:

1. Open `/profiles?provider=claude` (Claude shown, ChatGPT hidden).
2. Click Claude to hide it (empty-state view, URL becomes `/profiles?provider=`).
3. Reload or process popstate on that URL: **both providers reappear**. Saved storage stays unchanged.

Exact production JS was retrieved through GitHub contents pinned to the reviewed SHA into `/tmp/meridian-1411-review/`; no implementation rewrite or synthetic replacement. `bun /tmp/meridian-1411-review/probe.ts` emits:

```json
{"phase":"after-hide-last-chip","url":"http://127.0.0.1:3459/profiles?provider=","claudeHidden":true,"chatgptHidden":true}
{"phase":"reload","url":"http://127.0.0.1:3459/profiles?provider=","claudeHidden":false,"chatgptHidden":false}
```

`bun test /tmp/meridian-1411-review/regression.test.ts`: **1 pass / 1 fail**, normal one-provider URL + untouched preference positive control passes, all-off reload fails (`Expected true; Received false` at line28). Receipts: `regression.stdout.txt`, `regression.stderr.txt`. This is scoped pure browser-JS state proof, not browser layout/actual-page acceptance. Parent should escrow the regression and concise finding in the durable handoff/PR; `/tmp` is not durable evidence by itself.

Correction needs an unambiguous serialized empty selection (or a deliberate revised all-off policy) and parsing that round-trips it while preserving invalid/unknown-value fallback, anchors, unrelated query fields and existing saved preference semantics. Existing tests explicitly assert empty parameter falls back, so simply changing parsing also requires revisiting that deliberate rule/test.
